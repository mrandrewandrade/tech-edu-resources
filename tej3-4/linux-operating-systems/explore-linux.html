Set Up Your Accounts and Explore Linux

Linux
Linux Mint
accounts
networking
software
Bash
Git
Bashcrawl
Create accounts for yourself and two other students, personalize Linux Mint, test networking, install software, and begin a Bashcrawl command-line adventure.

The main goal of this assignment is simple: have fun with Linux and make the computer useful. You will create real accounts, explore the desktop, connect to the network, install something interesting, and finish with a short command-line adventure.

Class materials

  • Linux Start Here slides
  • Make a copy of the Explore Linux assignment

What you already know

You have probably created an account on a phone, Chromebook, game console, or Windows computer. Each person gets their own files, settings, wallpaper, and preferences. Linux accounts work in a similar way.

Linux Mint also has a menu, an app store, network controls, and a file manager. The names and layout are different from Windows, but the purposes are familiar. Explore first. You do not need to memorize everything.

Before you begin

You need:

  • the assigned classroom computer with Linux Mint installed;
  • the min account and classroom password pcss;
  • the account names or aliases supplied for the two other students;
  • the classroom Wi-Fi credentials; and
  • your copy of the Explore Linux assignment.
WarningUse only the assigned classroom computer

Do not change accounts or files on another computer. Do not use guest Wi-Fi, scan the school network, or try to connect to another person’s computer. Never submit or write a password in your Google Doc.

Part 1: create three real user accounts

Sign in as min. Open Menu > System > Users and Groups, then select Unlock. Enter the classroom password when Linux asks for administrator approval.

Create these three accounts:

Account Username Account type Password
Your account Create a unique, school-appropriate username with no spaces Administrator Create a private password you can remember
Other student 1 Use the name or alias supplied by your teacher Standard Use the temporary password supplied by your teacher
Other student 2 Use the name or alias supplied by your teacher Standard Use the temporary password supplied by your teacher

Your username should not contain your student number, email address, or full legal name. A first name or school-approved nickname is enough. Record all three usernames, but do not record any passwords.

Your account is an administrator because you will maintain this assigned computer and install approved software. The other two accounts are standard accounts so those students can explore and work without accidentally making system-wide changes.

Keep the min account. It is the classroom recovery account.

Test the accounts

  1. Sign out of min and sign in to your new account.
  2. Confirm that your home folder and desktop are separate from the min account.
  3. Sign out and test the first other student’s account.
  4. Confirm that it opens normally and has a separate home folder.
  5. Repeat the test for the second other student’s account.
  6. Sign back in to your own account for the rest of the assignment.

If an account does not work, stop and fix it before customizing the desktop.

Part 2: make Linux feel like your computer

Linux is highly customizable. You can change how the desktop looks and how you move through it without replacing the operating system.

Visual challenge: make it better for you

Take a screenshot of the default desktop. Then make at least one purposeful visual change that improves how the desktop looks or feels for you.

You could change:

  • the wallpaper or background colour;
  • the window theme or icon style;
  • the panel position, size, or colour;
  • the application launchers on the panel;
  • the desktop icons and how they are arranged;
  • the font size or display scaling; or
  • the terminal colours and font size.

Use the themes, wallpapers, and settings already included with Linux Mint for this assignment. Do not download a theme or run a customization script from an unknown website.

This is only one example. A good desktop does not need to look exactly like it. The example uses a calm wallpaper, a readable theme, a small set of favourite applications, an uncluttered desktop, and a panel that keeps the network, sound, and clock easy to find.

Take an after screenshot. In your Google Doc, name the change and explain why it made the desktop better for you. Your reason might be appearance, readability, accessibility, organization, or speed.

After the required visual challenge, use the GUI to complete at least three more activities:

  • explore the Xfce panel and application menu;
  • choose an account picture;
  • find the computer’s processor, memory, and storage information;
  • create a folder named Linux Lab in your Documents folder;
  • take a screenshot and find it in the File Manager;
  • find an accessibility setting that could make the computer easier to use;
  • adjust the display, sound, mouse, or keyboard settings; or
  • discover another useful setting and explain what it changes.

Do not remove the network, sound, clock, or application-menu controls from the panel. If you change something you cannot restore, ask for help instead of guessing.

Record what you changed and one thing you discovered in your Google Doc.

Part 3: check the network with the GUI

  1. Select the network icon in the panel.
  2. Connect using the classroom Wi-Fi credentials. Do not use guest Wi-Fi.
  3. Open the connection information or network settings.
  4. Record the connection name, whether it uses Wi-Fi or Ethernet, and the local Internet Protocol version 4 (IPv4) address.
  5. Open the browser and visit the TEJ Notes website.

Your local IPv4 address identifies the computer on the current network. It may change later. Include it in your private classroom submission, but do not post it publicly.

If the website works but another network test later fails, the network may simply block that type of test. One failed test does not always mean the internet is broken.

Part 4: install something useful and something fun

Open Software Manager from the application menu.

  1. Search for Git and install it if it is not already installed. Git will download the command-line game later in this assignment.
  2. Choose one additional school-appropriate game or useful application.
  3. Read its description before installing it.
  4. Install it using your own administrator password when prompted.
  5. Open it and try it for at least five minutes.

Possible choices include a drawing program, audio editor, media player, educational game, puzzle, or programming tool. Large 3D games may run poorly on older classroom hardware, so check the download size and system requirements first.

Record:

  • the exact software name;
  • what the software does;
  • why you chose it;
  • whether it worked properly; and
  • one thing you liked or disliked.
ImportantInstall from trusted sources

For this assignment, use Software Manager and the official Bashcrawl GitLab repository. Do not paste installation commands from advertisements, forums, comments, or random videos.

Part 5: meet the terminal

The terminal is a text-based way to give instructions to the operating system. It is not automatically better than the GUI. It is useful when a task is faster, clearer, repeatable, or only available as a command.

Open Terminal and run one command at a time. Input blocks are black and copyable. Example output is shown separately and is not a command.

Show the current user

Input

whoami

Example output

sam

whoami prints the account currently using the terminal. Your username will be different.

Show the computer name

Input

hostname

Example output

min-tej-14

hostname prints the computer’s network name. Classroom computers should not all have the same name.

Show the current location

Input

pwd

Example output

/home/sam

pwd means print working directory. A directory is a folder, and the output is the path to your current location.

List visible files and folders

Input

ls

Example output

Desktop  Documents  Downloads  Music  Pictures

ls lists the visible contents of the current directory. Names vary by account and computer.

Use the Up Arrow to bring back your previous command. Press Tab while typing a file or directory name to try automatic completion.

A quick network check

Show the network interfaces and addresses:

Input

ip -brief address

Example output

lo      UNKNOWN  127.0.0.1/8
wlp2s0  UP       192.168.1.24/24

The interface names and private addresses vary. Keep usernames and local addresses in the private class submission when evidence is required.

Show the path used to reach other networks:

Input

ip route

Example output

default via 192.168.1.1 dev wlp2s0

With teacher approval, you may also try:

Input

ping -c 4 andrewandrade.ca

Some school networks block ping. If it is blocked, record the result and use the working website in your browser as your main internet test.

Part 6: clone and play Bashcrawl

Bashcrawl is a simple text adventure that teaches terminal navigation. The game provides clues in files and directories. You move through it with commands such as ls, cd, and cat.

First, confirm that Git is installed:

Input

git --version

Example output

git version 2.43.0

Your version number may differ. If the terminal says the command was not found, return to Software Manager and install Git.

Return to your home directory. ~ is a shortcut for your home path.

Input

cd ~

Create a Games directory. mkdir means make directory; -p avoids an error if the directory already exists.

Input

mkdir -p Games

Enter the directory. This is a relative path because Games is named from the current location instead of beginning at the filesystem root.

Input

cd Games

Download the official Bashcrawl repository into a new bashcrawl folder.

Input

git clone https://gitlab.com/slackermedia/bashcrawl.git

Example output

Cloning into 'bashcrawl'...
remote: Enumerating objects...
Receiving objects: 100% (...)

git clone downloads a working copy of a repository. It does not require sudo. Never add sudo to this command.

Enter the game’s entrance directory.

Input

cd bashcrawl/entrance

List the entrance files, then read the first clue.

Input

ls

Input

cat scroll

cat prints a file’s contents. The first clue tells you what to inspect next.

Use these commands one at a time as the clues require them:

  • pwd checks your current location;
  • ls lists visible contents;
  • ls -a also shows names that begin with a dot;
  • cat filename reads a named file;
  • cd directory enters a directory you can see; and
  • cd .. moves to the parent directory.

Replace filename and directory with names you actually see. Do not type the angle brackets shown in some game instructions.

If you are in the wrong directory, run pwd, use cd .. to move up one level, and use ls before choosing the next path. To begin again without deleting anything, run cd ~/Games/bashcrawl/entrance.

Finishing the game is optional. Curiosity, careful reading, and trying commands are the point.

If a game instruction asks you to run a command you do not understand, read the clue again, use command --help, or ask your teacher. Do not use sudo anywhere in Bashcrawl.

Why Bashcrawl is the first game

Bashcrawl is the required first game because it is small, runs locally in a real terminal, begins with only a few commands, and leaves useful evidence in Bash history.

If you enjoy it, two good next steps are:

  • GameShell, which has more structured missions but needs extra software and runs a downloaded game script; and
  • OverTheWire Bandit, which adds Secure Shell (SSH), remote accounts, passwords, and more challenging puzzles.

Use those only with teacher approval. Bandit fits better in a later networking and remote-administration lesson.

Part 7: submit your Bash history

Bash keeps a history of commands typed by your account. This lets you review your work and gives your teacher evidence of the path you tried, including mistakes and corrections.

Create a text file on your desktop:

history > ~/Desktop/linux-bash-history.txt

Open linux-bash-history.txt with the GUI and read it before submitting it to Google Classroom.

The file must not contain passwords, private information, access tokens, or Wi-Fi credentials. Passwords entered into a normal password prompt are not shown in Bash history. If you accidentally typed a password as part of a command, do not submit the file. Tell your teacher and change that password.

Complete your copy of the Explore Linux assignment.

Submit exactly two files in Google Classroom:

  1. One Google Doc containing the required answers and screenshots
  2. Your reviewed linux-bash-history.txt file

Your Bash history is evidence of exploration, not a speed contest. A useful history can include mistakes, repeated commands, and corrections.

Helpful resources

  • Review the Linux Start Here class slides for the installation, account, terminal, and Bashcrawl sequence.
  • Read the official Bashcrawl instructions if you need help starting the game.
  • Review the Bashcrawl project on GitLab to see where the game came from.
  • Read the Git documentation for git clone when you want to understand the download command in more detail.
  • Use the Ubuntu command-line tutorial for another beginner-friendly introduction to the terminal.
  • Read the GNU Bash explanation of command history to learn what Bash saves and when it writes the history file.
  • Explore the school-appropriate Learn Linux TV YouTube channel for beginner Linux and terminal demonstrations.
  • Try Linux Journey for free, short lessons about commands, permissions, processes, and networking.

Review

On this page, you:

  • created your administrator account and standard accounts for two other students;
  • personalized Linux Mint through the GUI;
  • checked the classroom network and opened a website;
  • installed Git and another application from Software Manager;
  • used a few basic terminal and networking commands;
  • cloned and explored the Bashcrawl game; and
  • exported and reviewed your Bash history for Google Classroom.

The next lessons will build on this experience with files, permissions, software, and more advanced networking. Linux should feel like a computer you can explore, not just a list of commands to memorize.

Reflect on your learning

  1. What made Linux feel most like your own computer?
  2. Why is your account an administrator while the other two student accounts are standard?
  3. Which application did you install, and would you recommend it to another student?
  4. What did git clone do?
  5. Which Bashcrawl command was most useful, and what did it do?
  6. What mistake did you make in the terminal, and how did you recover from it?
  7. What would you like to customize, install, or learn next?
